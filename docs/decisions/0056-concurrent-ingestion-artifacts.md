# 0056 并发摄取、解析产物与引用来源

- DATE: 2026-10-07（2026-10-09 合并整理）
- TAGS: ingest, storage, citation
- STATUS: 当前
- SUPERSEDES: 0012、0044 的 worker 条款；其项目删除顺序合并进 0043

## DECISION

单机独立 worker 以可配置的有界线程池并发处理不同论文；同一 PDF 哈希对应一篇论文，同一论文同时只有一个活跃摄取任务。PostgreSQL 仍作为任务队列，不引入 Redis 或独立消息队列。生产环境必须使用 S3 兼容对象存储且启动时验证可用；本地文件适配器只用于开发与测试。运行中对象存储不可用返回 503 `provider_unavailable`。MinerU 的结构 JSON、Markdown、图片按 job 版本写入对象存储，写完清单才发布数据库指针；切块读取已发布清单并校验正文。Chunk 保存页码、block ID、块内字符范围与可用坐标；登记引用时复制来源定位和产物版本，避免重新切块后丢失证据来源。

业务 API 只把摄取 job 写入数据库，worker 按创建时间领取 queued job，启动时将遗留 running job 与 stage 退回待执行；不在 API 进程执行 MinerU。

## REJECTED

- 当前引入 Redis/Celery/独立消息队列：单机低并发无需多一套部署与恢复状态。
- API 进程直接解析或只用内存任务状态：阻塞服务，且重启无法恢复。
- 把解析另做 HTTP 服务：当前无需独立扩缩容，会增加服务契约与鉴权。
- 以 PDF 哈希固定路径原地覆盖解析产物：中途失败会混入新旧版本。
- 生产环境只写本地目录：后续服务器部署必须具备独立对象存储。

## RATIONALE

并发发生在不同论文之间；解析产物与引用绑定不可变版本，失败不发布半成品。

## OUT OF SCOPE

多 worker 实例租约、跨机调度、引用区域高亮、历史无清单产物的批量迁移。

## OPEN

生产级 S3 服务部署回测；本地 RustFS 和两篇小体量真实 PDF 的并发处理已通过。
