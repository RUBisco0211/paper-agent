# 0056 并发摄取、解析产物与引用来源

- DATE: 2026-10-07
- TAGS: ingest, storage, citation
- STATUS: 当前
- SUPERSEDES: 0044 的单任务 worker 条款；保留其项目删除顺序

## DECISION

单机独立 worker 以可配置的有界线程池并发处理不同论文；同一 PDF 哈希对应一篇论文，同一论文同时只有一个活跃摄取任务。PostgreSQL 仍作为任务队列，不引入 Redis 或独立消息队列。生产环境必须使用 S3 兼容对象存储且启动时验证可用；本地文件适配器只用于开发与测试。MinerU 的结构 JSON、Markdown、图片按 job 版本写入对象存储，写完清单才发布数据库指针；切块读取已发布清单并校验正文。Chunk 保存页码、block ID、块内字符范围与可用坐标；登记引用时复制来源定位和产物版本，避免重新切块后丢失证据来源。

## REJECTED

- 当前引入 Redis/Celery/独立消息队列：单机低并发无需多一套部署与恢复状态。
- 以 PDF 哈希固定路径原地覆盖解析产物：中途失败会混入新旧版本。
- 生产环境只写本地目录：后续服务器部署必须具备独立对象存储。

## RATIONALE

并发发生在不同论文之间；解析产物与引用绑定不可变版本，失败不发布半成品。

## OUT OF SCOPE

多 worker 实例租约、跨机调度、引用区域高亮、历史无清单产物的批量迁移。

## OPEN

真实 MinerU 多篇 PDF 并发负载与 S3 服务的部署回测。
