# 0043 会话删除按双库顺序清理

- DATE: 2026-10-06
- TAGS: api, security, frontend
- STATUS: 当前
- SUPERSEDES: —

## DECISION

浏览器删除绑定会话时，先调用 AgentScope 删除会话及历史，再调用业务服务删除当前用户的 `session_binding`；业务库通过外键级联删除已登记引用。AgentScope 返回会话已不存在时仍尝试清理绑定，以支持失败重试。业务绑定不存在或不属于当前用户均返回 404。任一步失败均保留确认界面并提示重试。

## REJECTED

- 只删除 AgentScope 会话：业务库会残留可读取的引用和范围绑定。
- 先删除业务绑定：AgentScope 删除失败会留下无法检索的会话，且已登记引用不可恢复。
- 跨库事务：两个独立 database 与框架服务之间没有共享事务。

## RATIONALE

先删除会话可避免把仍存在的会话变成不可检索状态；后续绑定清理可重试。

## OUT OF SCOPE

删除项目、文献或其他用户的会话。

## OPEN

进程在两步间退出时可能残留业务绑定；后续可增加孤儿绑定对账清理。
