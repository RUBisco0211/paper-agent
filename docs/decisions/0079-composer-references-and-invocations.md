# 0079 输入框资源引用、技能与流程指令

- DATE: 2026-10-10
- TAGS: agent, frontend, data, security
- STATUS: 当前
- SUPERSEDES: —

## DECISION

- 输入框使用 `@` 选择上下文资源、`$` 显式选择已安装 Skill、`/` 选择预设执行流程或专门 Agent；只展示实际可执行的候选。普通文字仍可直接发送。选中项变成带类型与显示名的 token，发送时传结构化引用，不靠模型解析标题或自由文本。`/summary`、`/compare` 可先作为明确标注的单 Agent 提问模板；只有编排真正接通后才标为子智能体流程。
- 后端发送链路先在 AgentScope 入口接收“正文 + 结构化引用”，由业务服务解析并校验会话范围内的文献/块；消息引用由 AgentScope 按当前会话读取并核对角色与完成状态。校验后生成有界的本轮上下文与检索目标，再构造 `UserMsg`；目标由服务端闭合到工具执行上下文，不新增可由模型填写的范围参数。
- `@文献` 以用户文献条目为目标；`@块` 指向同一文献的某个 MinerU 原始 block，附解析产物版本、页码与选中文字范围。前端提交 `user_paper_id`、block 序号等**定位字段**；业务服务逐次校验用户、会话范围、文献归属及版本，失效时要求重选。文献引用约束本轮检索目标，但不改变会话的全局/项目范围，不把整篇正文或项目文献清单注入提示词。
- 对 Assistant 消息或文献选中文字“评论并加入提问”使用统一的引用记录：`kind`、`selected_text`、`comment` 和按来源类型区分的定位字段。消息引用保存同一会话的 `source_message_id`、文本 content block 序号、**渲染后可见文字**中的选区起止位置及文本快照，不映射 Markdown 原文偏移。后端校验来源消息归属、角色、完成状态与文本块类型，暂不校验选中文字内容；前端恢复时按偏移核对快照，失配时不画错误高亮。文献引用分 `parsed_block`（`user_paper_id`、解析版本、block 序号、页码及块内范围）与 `pdf_selection`（`user_paper_id`、PDF 文件版本、页码、选区矩形及可见文字）两种来源；每条引用随新 user 消息存入正式 `Msg.metadata`，无需另建独立标注表。
- 三种引用在输入框里统一显示带 hover 详情的 badge，添加时无需先填评论，发送前可移除或在 Popover 中编辑评论；空评论有效。每次提问最多引用 8 处。已发送消息保留 badge，点击定位到来源。历史 Assistant 消息选中文字后右键菜单提供带图标的评论和复制；选择评论才在原处显示单行编辑区及荧光标注，自动聚焦输入框，以 Ctrl+Enter（macOS 为 Command+Enter）提交。加载历史消息时恢复来源文字标注，行内评论默认收起，点击对应 badge 后只展开该条，点击空白处收起；badge 描边、文字标注与评论强调色一致。会话右栏的文献阅读器在 PDF 同页文本选区右键菜单及解析块操作中提供“添加到对话”，随即加入当前会话输入框；独立文献页不绑定会话。
- 公式和代码解析块可作为文字引用；图片、图表解析块可作为多模态引用。服务端先核验用户、会话范围、解析版本、块类型和图像存在性，再将图像作为 `DataBlock` 随 `UserMsg.content` 送入模型；单图像上限 5 MiB。对已知会丢弃图像块的 DeepSeek formatter 在发送前拒绝并提示切换模型；其他模型的图像能力仍由 Provider 检查，不能伪称看过图片。结构化定位字段仍只进 metadata，模型看到的文字只包含来源说明及可用的图注或公式。
- PDF 文本层选区无需先找到 MinerU block 才能评论。服务端校验文献归属、会话范围与 PDF 版本，保存页级定位和用户所选文字；浏览器选区矩形逐个保存有效区域，不设数量上限，也不合并不同文字片段；坐标只用于前端定位，不进入模型文本。同页 block 的矩形重叠与规范化文本匹配仅用于补充可选的 `matched_blocks`，跨块可有多个。匹配失败时仍可跳 PDF 页，但不声称文本已经与解析块核对，不伪造 block ID 或正式 Citation。解析块选区则须按原块文本核对；现有 `blocks_index.json` 只有前 1200 字预览，实施该核对需提供完整规范化块文本索引。
- AgentScope 2.0.6 的 SQL 存储会持久化 `Msg.metadata`，但现用 formatter 不会把 metadata 自动交给模型。因而服务端还须将带来源状态的快照渲染为 `UserMsg.content` 中的有界、可读引用段（来源、引文、逐条评论和用户正文），同时保留 metadata 的结构化定位。历史重放读取已保存的内容段，不随文献重解析悄悄改写旧提问；引用段明确标记为来源内容而非系统指令。不能只发 JSON metadata，也不依赖模型解析未校验的前端 Markdown。
- 给模型的本轮上下文是有界的来源标题、页码/消息角色、引文与用户评论；PDF 选区只显示文献与页码，解析核对状态留在服务端，不向模型解释内部机制。仅在工具确需时使用**会话已登记** `citation_id`。原始 `msg_id`、数据库 UUID、对象存储路径、block 序号和解析版本只在传输及服务端解析层使用；保护来自每次归属与范围校验。未映射已登记证据时不生成正式 Citation ID；缺可靠页码也不编造。
- 第一阶段实现 `@文献`、`@块`、已完成 Assistant 消息的选中评论，以及解析块和 PDF 文本层两种文献评论；PDF 与 MinerU 块的自动匹配可后补。`/summary`、`/compare` 仅作为可编辑模板。`$Skill`、主动子智能体、固定多智能体编排、跨会话引用和持久文献标注后置。第一阶段不新增 Agent 写工具。

## REJECTED

- 仅发送选中文字、不带来源定位：无法核验原文、恢复跳转或区分同名文献。
- 把消息 ID、块 ID 或数据库 UUID 当作模型理解引用的主要方式：语义贫乏且容易被模型错用；只在后端定位或既有工具契约确需时保留。
- 将 `@文献` 解释为修改会话范围，或把全文、项目文献清单直接塞进提示词：违背 0025 的范围与按需读取约束。
- 将尚未实现的 Skill 或多智能体流程做成可选入口：界面会承诺不存在的能力。

## RATIONALE

消息引文与文献引文都需要“选中文字 + 用户评论”，但校验源、稳定定位与 Citation 资格不同。统一外层便于输入框和消息展示复用，保留带类型 locator 才能在后端分别验证。内部 ID 可出现在授权 API 请求中，无需作为模型可见语义；模型拿到可读来源与已登记证据即可。

## OUT OF SCOPE

持久标注、跨会话历史合并、会话范围变更、任意自定义 Skill/Agent、精确 PDF 区域高亮。

## OPEN

- PDF.js 选中文字与 MinerU block 文本不一致时的可选匹配阈值，用真实样本确定；不阻塞 PDF 页级评论。
- 验证多模态 Provider 对 `DataBlock` 的实际支持及失败文案；验证 AgentScope 的消息写入时机，确保服务端生成的 `content` 与 `metadata` 同次持久化。
