# 0081 邮箱验证、密码找回与定时任务邮件通知

- DATE: 2026-10-17
- TAGS: security, product, agent, data, arch
- STATUS: 当前（已批准；不代表实现或联调验收通过）
- SUPERSEDES: 仅 0022 中“不做邮箱验证/找回密码”及以“无 Redis”为理由的否决、0035 中“只验签并容忍撤销后最多 15 分钟”及否决逐请求回查的片段、0049 中“通知投递不在范围内”及禁止为邮件 outbox 保存最终结果快照的相关片段；其余约束和否决理由继续有效。

## DECISION

- 注册与找回密码是彼此独立的三步流程：填写邮箱并发送验证码 → 校验验证码并取得用途绑定的一次性凭证 → 设置并确认密码；两种用途不可互换。密码 8–128 字符，必须二次确认；密码哈希仍用 Argon2id。
- 注册发送验证码前先按归一化邮箱检查账号；已注册立即返回 `409 / email_already_registered`，不生成验证码或入队邮件；正式注册仍保留重复检查与唯一约束兜底。找回密码的不暴露未知账号行为不变。
- 验证码有效期 10 分钟，重发冷却 60 秒，错误校验累计 5 次后失效；发送上限每邮箱每小时 5 次、每 IP 每小时 20 次。Redis 保存临时验证、一次性凭证及冷却/限流状态，不保存账号、登录会话或持久邮件队列；状态丢失须重新验证，Redis 不可用不得绕过校验。
- 密码重置成功撤销该用户全部登录会话，并发送安全通知邮件；AgentScope 每个认证请求通过 HTTP 回查业务登录态，已撤销的旧 token 不再可用。业务服务不可用时不能仅验签放行；不共享业务用户表。JWT/Refresh 轮换与 family 撤销规则继续有效。
- PostgreSQL 加密 outbox 承载邮件，独立 `python -m app.platform.mail_worker` 进程通过 SMTP 投递；不引入 Celery，不把 Redis 当投递队列。临时错误退避重试至多 5 次，永久拒绝立即失败，过期验证码不发；`accepted` 只表示 SMTP 接受，不保证到达收件箱，崩溃窗口可能重复投递。投递后清除正文，保留状态；加密密钥随 Credential 主密钥管理，开发未配置时使用 JWT 密钥派生。
- 定时任务邮件通知默认关闭，只发往任务所属用户的已验证邮箱。Agent 工具仅增加通知布尔值，不接收收件地址，不增加新的 always-allow 权限；沿用已有任务创建授权，不因邮件通知扩大写权限。
- 成功通知使用本次运行最终完整回答 Markdown，生成安全 HTML 和纯文本两种正文并附站内运行链接；失败通知只给可行动错误和运行链接，不发送 partial 回答。最终结果快照只供 outbox 投递，不成为第二份会话历史，不改变 AgentScope 对 messages 的所有权。
- 邮件公式保留 LaTeX；图片使用说明与站内链接，不依赖邮件客户端执行公式脚本或加载私有资源。超出邮件大小限制时明确提示仅展示部分，并链接完整站内结果，不静默截断。
- `PUBLIC_APP_URL` 是浏览器可访问的可信站点根地址，邮件运行链接沿用 `/scheduled/:scheduleId/runs/:sessionId`；点击后仍须登录并校验任务和运行归属。
- SMTP 配置为 `SMTP_HOST/PORT/USERNAME/PASSWORD/FROM_EMAIL/FROM_NAME/SMTP_USE_SSL/SMTP_STARTTLS`；另配 `REDIS_URL`、`PUBLIC_APP_URL`。QQ SMTP 使用独立授权码；真实凭据仅由主 agent 写入不提交的 `backend/.env`，配置示例值全部留空。
- Compose Redis 为 `redis:7-alpine`，使用标准 `6379`；本机不得再运行第二个 Redis。应用容器部署使用 `redis:6379` 服务名。启动脚本校验宿主机连接 `run_id` 必须与 Compose 容器一致，禁止静默回退到宿主机 Redis。默认不持久化，可按部署需要启用持久化，但正确性不依赖保留临时状态。根 `.env` 保留用于 Compose 插值，与 `backend/.env` 分工，不合并秘密配置。
- 启动探针不伪造用户/JWT，不添加生产认证绕过：业务 API 使用公开 `/health`；当前 AgentScope `/health` 需认证，启动脚本仅检查进程与 TCP 就绪，不声称完整业务健康。

## REJECTED

- Redis/Celery 持久邮件队列或在 API 请求中同步等待 SMTP：分别扩大依赖/状态边界或阻塞交互；采用 PostgreSQL outbox 与独立邮件进程。
- Agent 自选收件地址、默认开启通知或新增 always-allow：扩大数据外发与授权范围。
- 重置密码后仍容忍旧 access token 15 分钟、伪造 UUID=0 探针或放宽生产鉴权：不满足会话撤销与认证边界。
- 邮件发送失败/partial 冒充成功、静默截断正文或邮件运行链接免登录：误导用户或泄露数据。

## RATIONALE

Redis 只承担可丢弃的短期原子验证状态；PostgreSQL 保留可靠投递记录。通知是用户显式选择的数据外发，不改变任务范围、独立运行会话与既有授权语义。

## OUT OF SCOPE

Celery、多实例部署、通用邮件/任意收件人 Agent 工具、管理员后台、邮件内交互与公式脚本渲染；不扩大 0049 的任务自动重试范围。

## OPEN

- 旧账号数据清理意愿已确认，但执行范围尚未确认；不得执行清理，须另行确认数据库、对象存储及 AgentScope 数据的范围。
- 真实收件确认与浏览器端到端验收待用户提供测试账号后完成；自动测试与 SMTP 接受不替代浏览器闭环验收。
