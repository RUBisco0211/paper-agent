# Paper Agent 最小 MVP 功能规格

> 术语：本文用「文献」指代用户可见的文献条目，「全局」指覆盖个人全部文献的默认会话范围
> （旧文中的「论文」「个人全库」已统一为本表述）。
>
> 状态：功能规格已整理，按本轮 Q1–Q5 的回答收敛；仅编写文档，尚未开始实现。
> 日期：2026-09-16。
> 本轮明确新增：交付后端 API 和可实际使用的 React 前端，组件库使用 shadcn/ui。
> 旧架构基线见 [prototype.md](prototype.md)；本轮决策与旧记录审计见 [mvp-scope-review.md](../grilling/mvp-scope-review.md)。本轮功能范围以本文为准；未涉及的基础架构沿用旧原型。“实现建议”不表示对应代码已存在。

## 1. 目标与边界

MVP 要让用户在浏览器中完成文献入库、查看解析状态、组织阅读范围、与 Agent 问答，并打开原文验证答案。验收必须包含真实前后端联调，不能只有页面样机或 OpenAPI。

### 1.1 已明确与沿用的基线

| 项目 | 当前基线 | 依据 |
|---|---|---|
| 交付形态 | 同一项目交付后端 API 与 React + shadcn/ui 前端 | 本轮用户明确要求 |
| 用户 | 多账号，注册、登录、刷新登录态、退出，个人数据互相隔离 | 沿用原型，不因“最小”自动删除 |
| 文献输入 | 英文 born-digital PDF 上传 + DOI/arXiv 导入；支持仅元数据条目 | 本轮 Q1、Q5 |
| 文献组织 | 个人文献库与项目；项目是个人文献库子集 | 沿用原型 |
| 问答范围 | 全局会话（可见全部文献）、项目会话、单篇文献会话；范围不可被 Agent 突破 | 本轮细化：全局与单篇文献需要区分 |
| 正文解析 | MinerU API；原始结构、Markdown 与图片留存 | 沿用原型 |
| 元数据 | 去掉 GROBID，采用 Agentero 式轻量 PDF 识别与在线元数据补全 | 本轮已确认；具体链路见 F03 |
| 检索 | PostgreSQL 英文全文检索 + pgvector + RRF，不做 rerank | 沿用原型 |
| Agent | AgentScope 执行，固定只读文献工具 | 沿用原型；调研不自动增加写工具 |
| 会话持久化 | 自有 Session + Entry；历史与框架内部 ID 解耦 | 沿用原型 |
| 配置 | MinerU/Embedding 实例级；LLM 配置由用户在前端维护 | 沿用原型 |
| 部署 | 单机 Docker Compose；沿用原型基础设施，去掉 GROBID | 本轮调整 |

### 1.2 本轮已确认的范围

| 决策 | 确定范围 | 对交付的影响 |
|---|---|---|
| Q1 文献入口 | 本地 PDF 上传 + DOI/arXiv 导入；标题/关键词联网搜索后置 | 增加标识符导入对话框、元数据查询与 PDF 获取 |
| Q2 PDF 元数据 | 暂时去掉 GROBID，参考 Agentero 的上传识别流程 | 不部署 GROBID；轻量识别后通过标识符补全 |
| Q3 会话 | 保留 steering/follow-up；分支与导出后置 | 保留队列与安全投递边界，不做分支/导出 UI |
| Q4 引用 | 参考 Agentero，复杂引用设计后置 | 基础来源、已有页码/片段及 PDF 打开；不做精确区域高亮或图表交互 |
| Q5 无 PDF 的导入 | 参考 Agentero：保留元数据条目，后续补全文 | 文献库支持“待补全文”，不把下载失败等同于入库失败 |

Q4 的最小落地解释：利用解析已有信息提供基础来源核对，不为第一版建立额外版面索引、章节模糊定位、多区域高亮或完整图表工具。引用不得编造，用户与项目范围校验仍适用。

Q5 依据 Agentero 的实际流程落地：先写文献元数据，再尝试下载资产；下载失败保留条目，允许重新获取或手动补传 PDF。参考 [入库实现](https://github.com/poco-ai/Agentero/blob/81ddfe39f59e359cb951c2ebcb6a5bbc25889daf/crates/agentero-core/src/features/paper/import/paper_import/mod.rs)。

## 2. 浏览器主流程

已确认的基本流程：

```text
注册 / 登录
  → 个人文献库
  → 上传 PDF，或输入 DOI/arXiv 获取文献
  → 看到文献条目和后台处理阶段
  → 元数据 / 全文 / 索引逐步可用
  → 加入项目，或使用全局
  → 新建 / 打开会话
  → 提问 → 看工具执行摘要 → 接收流式答案
  → 点击引用 → 查看原文片段与 PDF
  → 离开后再次打开，能够读取历史
```

文献入库成功不等于取得 PDF，也不等于解析完成。文献可用能力决定界面可执行的动作；部分失败不能隐藏已有元数据、PDF 或全文。缺全文的条目可以加入项目并查看书目信息，但不能参与全文证据检索。

```text
DOI/arXiv → 元数据成功 → 条目入库 → 尝试获取 PDF
                                  ├─ 成功 → 共用解析/索引流程
                                  └─ 不可用 → 待补全文 → 重试下载 / 补传 PDF
```

## 3. 前端页面与可见行为

以下是建议的页面组织；路由名称和组件组合属于实现方案，可调整，不改变功能验收。

| 页面 / 区域 | 必须提供的行为 | 关键状态 |
|---|---|---|
| `/login`、`/register` | 注册、登录、表单校验；登录后回到文献库或原目标页 | 提交中、凭据错误、账号已存在、服务不可用 |
| `/library` 文献库 | 上传与 DOI/arXiv 导入入口、分页文献列表、按标题筛选、条目状态、查看详情、加入项目、对单篇文献提问 | 空库、加载失败、上传中、待补全文、处理中、部分可用、处理失败 |
| `/projects` 项目列表 | 创建项目、列表、重命名、删除 | 空列表、重名不影响身份、删除确认、删除中/失败 |
| `/projects/:id` 项目详情 | 从个人库选择文献加入项目，列出项目文献，创建或打开该项目会话 | 项目为空、文献处理中、无访问权限、项目已删除 |
| `/sessions/:id` 阅读工作区 | 明示全局/项目/单篇文献范围；历史消息、输入、流式答案、停止、工具摘要、引用；查看相关 PDF | 首次提问、生成中、已停止、重连中、中断、模型或检索失败 |
| 文献详情面板 | 标题、作者、摘要、标识符、来源；元数据识别状态；解析阶段、失败原因、重试；PDF 打开/补传/重新获取入口 | 元数据未识别、待补全文、部分字段缺失、PDF 可读但不可检索 |
| 模型设置面板 | 选择允许的 provider、填写模型与 API key、保存到浏览器本地 | 未配置、配置不完整；调用失败时提示修正 |
| 会话列表 | 按范围找到会话，创建、重命名、删除并重新打开历史 | 空列表、加载失败、删除中；分支和导出后置 |

前端采用 React 与 shadcn/ui。建议使用 TypeScript、桌面优先布局，以 Sidebar、Table、Dialog、Sheet、Tabs、Form、Alert 等基础组件构建；PDF 阅读器是独立集成能力，不假定 shadcn/ui 提供 PDF 渲染。框架脚手架与 PDF 组件版本在实施时确定。

“按标题筛选个人库”只筛选已有文献，不等同于联网文献搜索，也不增加独立的 RAG 搜索页。用户通过对话查证据；首版导入框只接受 DOI/arXiv 及其规范链接，不接受自由标题搜索或任意网页抓取。

## 4. 功能要求与验收

### F01 账号与登录态

- 用户可以注册、登录、刷新页面后恢复登录态和退出；不包含邮箱验证、找回密码或管理员后台。
- 前端按既定 Access token / Refresh cookie 契约调用 API；并发请求触发刷新时避免重复轮换。
- 未登录不能读取文献和会话；另一用户持有资源 ID 也不能访问其 PDF、索引证据、项目或历史。
- 验收：两个账号各自上传文献，列表、详情、搜索、PDF、引用与会话均不能互相越权。

### F02 上传与个人文献库

- 从页面选取本地 PDF，显示上传状态；后端校验格式、大小、基础可读性并计算 SHA-256。
- 上传接收成功后返回稳定的用户文献条目 ID 和 Ingestion Job 信息，页面立即显示条目，再进入后台处理。
- 对已有条目补传 PDF 时更新原条目；独立重复上传复用已有 PDF 关联，不制造无意义副本。跨用户复用解析产物但不暴露其他用户存在。
- 列表显示标题或文件名占位、加入时间、阶段和能力；只有元数据的条目显示“待补全文”，有文件后显示 PDF 入口。
- 原型暂不支持从个人库移除文献，不在首版界面放置无法兑现的删除入口。
- 验收：合法文件走通；非法文件明确拒绝；重复上传、页面刷新、后台处理失败均有可解释状态。

### F03 解析、元数据与阶段重试

- 按 metadata、fulltext、chunking、embedding 记录阶段；每次尝试有状态、错误和产物依据。
- 前端显示阶段名称与服务实际提供的进度；没有准确百分比时显示阶段，不编造总体百分比。
- PDF 接收后可以打开原始文件；元数据、全文和索引成功后分别开放相应能力。
- `has_pdf`、`has_metadata`、`has_fulltext`、`has_keyword_index`、`has_embedding` 与处理状态分开表达。没有 PDF 时不启动正文、分块和向量阶段。
- MinerU 结果验证所需字段、版本、图片路径和大小上限，保存原始产物；引用位置在离线阶段提取。
- 提供失败重试入口，只重做必要阶段；鉴权/额度错误明确提示，不能无限自动重试。
- 解析取消、换 Embedding 模型重建、多解析器自动回退仍后置。
- 元数据采用轻量识别与在线补全，详见下述流程；不安装或运行 GROBID。
- 验收：全文成功但向量失败时仍能读全文；重试不重复已有 Chunk，损坏或不兼容产物不能标成功。

**无 GROBID 的元数据流程：**

```text
上传 PDF → 文件名占位条目
  → 轻量读取前 5 页文本、行与词级布局（不做 OCR）
  → Zotero recognizer 识别
      ├─ DOI/arXiv → 精确在线查询完整元数据
      ├─ 只有标题/作者 → 保存已有识别结果
      └─ 未识别/服务失败 → 保留占位信息，可补填标识符再尝试
  → 正文处理独立继续，不因元数据未识别而阻断
```

Agentero 使用 liteparse/PDFium 在本地 worker 中生成词级布局，再将 JSON 发往 Zotero recognizer；不是用 MinerU 或 LLM 猜测元数据。该 recognizer 是未公开接口，源码明确不适合作为硬依赖。MVP 将其作为尽力而为的默认识别适配器：超时或不可用时保留已有数据，正文解析照常进行，界面显示可重试状态。用户已有 DOI/arXiv 元数据时跳过不必要的重新识别。[识别实现](https://github.com/poco-ai/Agentero/blob/81ddfe39f59e359cb951c2ebcb6a5bbc25889daf/src-tauri/src/features/paper/import/recognize/pdf_recognize.rs)、[轻量提取实现](https://github.com/poco-ai/Agentero/blob/81ddfe39f59e359cb951c2ebcb6a5bbc25889daf/crates/agentero-core/src/features/paper/analyze/parse/mod.rs)

- Python 本地提取器在实施时用样例验证页、行、词、字体、坐标是否满足识别输入；功能规格不预先宣称某个库与 liteparse 等价。
- metadata 状态区分识别成功、部分字段、未识别与服务失败；正文 ready 不要求 metadata 必须完整。元数据失败时可用文件名识别引用来源。
- 提供补填/修正当前用户条目 DOI/arXiv 的小表单并重新查询；不要求首版做完整书目编辑器。
- 元数据保留来源；异步识别不能覆盖用户刚提交的标识符/修正。用户修正只作用于用户条目，不能改掉其他用户的共享信息。
- 最小来源实现建议：arXiv 精确查询、Crossref DOI 查询；其他来源作为配置化补全适配器后续按命中率增加，不把完整六源搜索作为验收依赖。
- 不要求首版部署 Agentero 的 Translator 服务；本项目借鉴“布局识别 → 标识符查询”流程，元数据可直连来源 API。README 列明识别会发送部分文献文本布局，MinerU 会接收 PDF。


### F04 项目与问答范围

- 创建、列出、重命名和删除项目；可从个人库追加文献。
- 项目只能引用当前用户文献条目，包括“待补全文”条目；项目文献首版只增不减。补齐 PDF 不改变项目成员关系。
- 会话范围三选一，创建后不可改，并在界面持续可见：
  - **全局**：覆盖当前用户文献库全部条目（默认范围）；
  - **项目**：只覆盖该项目当前文献；
  - **单篇文献**：只覆盖该条目，用于针对一篇文献提问。
- 范围由后端注入文献工具；模型不能通过传参突破。无全文条目可以被列举，但不能伪装为已读取的全文证据。
- 删除项目不删除个人库中的文献，但按原型终止并清理项目会话；前端展示删除后果与处理中状态。
- 验收：同一问题在不同项目中只使用各自授权文献，新加入文献就绪后可被后续工具调用发现。

### F05 检索与 Agent 文献工具

首版沿用三种只读工具，借鉴 Agentero 的按需读取方式：

| 工具 | 输入原则 | 返回内容 |
|---|---|---|
| `list_papers` | 后端绑定会话范围；分页、有限字段 | 文献 ID、标题、必要元数据、可用能力 |
| `search_papers` | 查询文本；可在授权范围内进一步限定文献 | 有限证据片段、Citation ID、文献/页码、检索状态 |
| `get_paper_excerpt` | 已授权 Citation/Chunk | 原文、标题路径、页码和可用定位信息 |

- 工具与 HTTP 入口复用应用层权限和查询逻辑；模型不能通过传入 user_id 或扩大 scope 越权。
- 列表、检索结果与展开原文均有条数和总文本预算；不默认将整库正文注入上下文。
- 关键词与向量分别召回，RRF 融合；证据去重、相邻片段合并、每篇文献配额。
- 区分正常证据不足、检索通道降级与整体不可用。基础闭环在两通道正常时完成验收；降级不能伪装为完整混合检索。
- Agent 答案引用必须来自可验证证据；证据不足明说，检索失败不能解释为文献没有相关内容。
- 验收包含术语查询、语义查询、跨文献问题、无证据问题、检索服务故障和越权调用。

### F06 会话与流式回答

- 创建、列出、重开、重命名、删除会话；提交用户消息后显示流式回答和安全的工具摘要。
- 停止保留已生成内容并标记中断；已完成工具结果保留，未完成工具调用补齐错误/中断结果。
- 刷新页面后读取历史，并从事件游标衔接活动生成；后端重启造成的生成中断要明确展示。
- 用户离开页面不等于停止；当前生成与 SSE 订阅连接解耦。
- LLM key 只存在执行器内存，不进入 Entry、日志、任务队列或持久缓存。
- 生成中允许将新消息加入 `steering` 或 `follow_up`；界面以“调整当前回答 / 排队追问”解释两种方式，并显示尚未投递消息及队列顺序。
- steering 在当前 assistant turn 及工具批次结束后的安全边界投递；follow-up 在 Agent 原本准备停止且无 steering 时投递；两个队列各自 FIFO，一次消费一条。
- pending 在真正投递时才成为 user Entry；界面避免同时把同一条显示为排队消息和已发送消息。停止按原型保留 pending，删除会话时清空。停止或后端中断后，由用户点击“继续处理排队消息”并重新提供当前 LLM 配置；不要求发送一条占位消息才能恢复。
- 只做线性会话展示；分支和导出明确后置。模型配置变化继续由 Entry 记录，不因此增加复杂历史编辑界面。
- 验收：停止、刷新、短暂断网、模型报错后，历史不重复、不丢失工具配对、不把失败显示为成功完成。

### F07 阅读原文与验证引用

- 点击引用时显示文献标题、已有页码范围和原文片段，并打开页面内的相关 PDF。
- 引用按 Session 和用户校验，不接受模型任意生成路径或 Citation ID。
- 提供 PDF 的基本翻页和缩放；若已有可靠页码，尽量直接跳到对应页。没有可靠定位时显示来源文献与片段，不编造精确位置。
- 暂不做区域高亮、缩放/旋转坐标换算、章节模糊解析、独立图表浏览或图表问答工具；不为此引入新的 layout-index。
- 基础引用利用已有 Chunk/证据标识、文献 ID、片段和可用页码实现，无需额外复杂 Citation 持久化体系。历史引用仍需能从已保存工具结果/回答附带证据恢复。
- 验收：从真实答案引用能回到支持该结论的原文；未授权、伪造和不存在的引用均被拒绝。

### F08 DOI/arXiv 导入

- 用户在文献库或项目内打开导入对话框，输入 DOI、arXiv ID 或对应规范链接。
- 后端规范化输入，查询精确元数据并尝试获取公开可用的 PDF；不做自由标题搜索、任意 URL 爬取或绕过访问限制。
- 前端区分“查询元数据”“获取 PDF”“解析中”；查询错误、未找到文献、暂时限流与无可用 PDF 不能都显示为同一种失败。
- 元数据查询成功即保存用户文献条目，并尝试下载 PDF。成功后复用上传校验、SHA-256 去重及解析流程；已有标识符元数据保留来源，不重复猜测。
- DOI/arXiv 标识用于元数据查询和候选关联，不代替 PDF 文件身份；不同版本 PDF 的页码及 Chunk 不混用。
- 没有可用 PDF 或下载失败时，条目保留为“待补全文”；显示原因、原始来源链接、“重新获取 PDF”和“上传 PDF”入口，元数据仍可查看。
- 用户手动补传的 PDF 作为该条目的正文；若识别出明确冲突的 DOI/arXiv，提示冲突并保留原有数据，不静默覆盖或自动合并不同文献。
- 人工点击导入属于用户操作；当前 Agent 工具依然只读，不自动获得导入权限。
- 验收：arXiv 成功导入、DOI 成功导入、重复标识符、重复 PDF、查无元数据、来源故障、无 PDF 留库及补传后原条目可检索。

### F09 支持“仅元数据条目”的最小数据语义

本轮 Q5 改变了旧原型“有 PDF 才能存在文献”的前提，不能继续要求所有用户文献条目创建时都有 file_hash。

- 用户可见文献条目有独立、稳定的 ID；只查到元数据时就能创建、列出并加入项目，补传 PDF 后 ID 和项目关系不变。
- PDF 与解析产物仍按 SHA-256 共享去重；同 DOI 的不同 PDF 版本不得混用 Chunk 和页码。
- 同一用户重复导入相同规范标识符/明确版本时优先复用该条目；未知版本不靠模糊标题自动合并。无 PDF 时用标识符去重，拿到文件后再进行内容去重。
- 对某条目补传的 PDF 即使已存在于共享存储，也应复用文件与产物并保留原用户条目身份；两个明确不同版本条目不因 DOI 相同被强行合并。

**实现建议：** 保留全局 Paper 作为 PDF/解析事实实体，让 User Paper 先持有书目快照与来源、允许暂时未关联 Paper；项目关联用户条目，取得 PDF 后再绑定全局 Paper。对外文献资源 ID 使用稳定用户条目 ID，内部共享 Paper ID 不作为越权访问依据。具体表名可调整，但上面的可见行为必须保持；不得填造假哈希绕过模型问题。

## 5. 前后端 API 对照

以下为待实现的建议接口，不表示当前仓库已经提供。统一 `/v1`、认证、稳定错误码和 request_id；所有身份归属来自认证上下文。路径中的 `paper_id` 指用户可见稳定条目 ID，可对应尚无 PDF 的条目；内部共享 Paper 的身份独立处理。

| 页面动作 | API 建议 | 说明 |
|---|---|---|
| 注册/登录/刷新/退出 | `/v1/auth/register`、`login`、`refresh`、`logout` | 沿用原型认证契约 |
| 上传/列文献 | `POST /v1/papers`、`GET /v1/papers` | 上传 multipart；列表分页和过滤 |
| 文献详情/PDF | `GET /v1/papers/{paper_id}`、`GET /v1/papers/{paper_id}/pdf` | 返回元数据、能力及授权原文 |
| 补充全文 | `POST /v1/papers/{paper_id}/pdf`、`POST /v1/papers/{paper_id}/fetch-pdf` | 手动补传或重新获取，不新建用户条目 |
| 标识符修正/补全 | `PATCH /v1/papers/{paper_id}/metadata`、`POST /v1/papers/{paper_id}/resolve-metadata` | 首版仅必要标识符字段及精确补全，不扩展为完整编辑器 |
| 处理进度/重试 | `GET /v1/ingestion-jobs/{job_id}`、`POST /v1/ingestion-jobs/{job_id}/retry` | 显示各阶段；轮询即可满足最低验收 |
| 项目管理 | `/v1/projects`、`/v1/projects/{project_id}` | 创建、列表、详情、重命名、删除 |
| 项目文献 | `GET/POST /v1/projects/{project_id}/papers` | 列表与追加，无移除接口 |
| 会话管理 | `/v1/sessions`、`/v1/sessions/{session_id}` | 创建（`project_id` 与 `paper_id` 互斥，都不传即全局）、列表（`scope=library\|project\|paper`）、详情、重命名、删除 |
| 历史/提问/停止 | `/v1/sessions/{session_id}/entries`、`messages`、`stop` | 支持 steering/follow_up；会话详情返回 pending 快照与顺序 |
| 继续消费队列 | `POST /v1/sessions/{session_id}/resume` | 提交瞬时 LLM 配置，继续已排队输入；不创建占位 user Entry |
| 流式订阅 | `GET /v1/sessions/{session_id}/events` | fetch + Bearer；支持事件游标 |
| 引用展开 | `GET /v1/sessions/{session_id}/citations/{citation_id}` | 按会话校验后返回证据位置 |
| 可测试检索入口 | `POST /v1/search` | 不要求前端增加独立搜索页 |
| 标识符导入 | `POST /v1/imports`、`GET /v1/imports/{import_id}` | 元数据入库后可返回条目 ID；PDF 获取失败保留条目 |

上传、消息提交及重试等会触发处理的操作应有幂等与并发约束。前端错误态必须能区分输入错误、权限问题、处理未就绪和供应商故障。

## 6. 明确后置的功能

沿用原型后置：团队共享、中文/扫描件 OCR、文献移除、rerank、多索引版本、笔记/标注、定时工作流、自定义 Agent、引文图谱、收费配额后台。React 前端不要求复制 Agentero 桌面文件树、插件市场或完整编辑器。

本轮已明确后置：联网标题/关键词搜索、会话分支和导出、精确区域高亮及复杂引用/图表交互。DOI/arXiv 导入、轻量元数据识别与在线补全、steering/follow-up 都属于此次交付。项目、全局、多用户隔离与已有持久化模型继续沿用。

## 7. 最小端到端验收与交付

| 场景 | 浏览器可观察结果 |
|---|---|
| 新用户首次使用 | 注册 → 配置模型 → 上传 → 看阶段 → 获得可读文献 |
| 成功问答 | 在全局/项目提问，看到工具摘要和流式答案，引用能核对原文 |
| 处理失败 | 看到失败阶段、已有能力与重试入口；重试后恢复 |
| 无证据/检索故障 | 前者说明证据不足，后者说明检索失败，文案和状态不同 |
| 多用户隔离 | 他人的文献、PDF、项目、引用、会话均不可访问 |
| 页面刷新/断线 | 历史可恢复，流可重连，无重复消息；后端中断明确显示 |
| 停止与删除 | 停止后保留中断回答；删除会话/项目时关联数据按约定清理 |
| DOI/arXiv 导入 | 可查元数据、获取 PDF、走共用解析；无全文时留库，补传后保持同一条目和项目关系 |
| 排队输入 | steering/follow-up 分别按安全边界投递，刷新后排队状态可恢复 |

交付物：可启动的 React 前端、FastAPI 后端、迁移与环境变量样例、单机部署说明、API 文档、关键自动化测试、浏览器端到端用例，以及小规模英文文献检索/引用验收样例。Yaak 集合继续辅助联调，不能替代浏览器验收。UI 样机或仅 mock 数据不算最终完成。

## 8. 建议实施顺序

1. 前后端工程、登录态、应用壳与统一错误展示。
2. 支持元数据条目的文献库、PDF 上传、轻量元数据识别与 MinerU 解析、PDF 阅读。
3. DOI/arXiv 导入与补全文，项目、检索和基础来源读取，验证授权与真实文献证据。
4. Agent 工具、流式会话、历史恢复、引用联动。
5. 完成标识符导入、元数据补全与 pending 队列的全部异常场景，部署并完成端到端验收。

每一步都交付可在浏览器验证的纵向功能。此文档确定产品行为，具体技术选型的小型验证和编码任务在实施阶段拆分，不扩张已明确后置的功能。
